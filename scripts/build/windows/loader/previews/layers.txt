# The launcher's embedded preview art: one base screenshot, plus one layer per option.
#
# GeneralsX @feature Claude 17/08/2026
#
# Parsed by PreviewArtSource.Parse. Everything here is DATA - no archive name, no default and no
# caption appears in the C#, so adding art for a new option is a .png and a line in this file.
#
# WHY THIS FILE EXISTS AT ALL, rather than the code just looking for "<archive>.png". Two of the
# three things a row has to say cannot be derived from the presence of a file: whether the BASE
# already shows an option (in which case turning it off is the state we cannot draw), and whether an
# option provably changes nothing a screenshot like this can show. Both are claims, and a claim
# without its evidence attached is exactly what this whole feature is trying not to be. So each one
# is written down next to the reason it is true.
#
# THE GRAMMAR - keyword first, same shape as gxchangelog.txt and gxpreviews.txt:
#
#   base <file>              the picture everything starts from. Required; without it there is no
#                            picture and every claim below is discarded.
#   caption <one line>       what the base IS, including which options it was captured with. Shown
#                            under the picture.
#   artifact <name>          the content-addressed optional-content zip the base was captured from.
#                            Compared against gxinstalled.txt; when the installed tier is a
#                            different one the picture is captioned as possibly out of date rather
#                            than presented as current. Omit it and the launcher cannot tell, which
#                            it treats as "current" - so omitting it is a decision, not a default.
#   shows <archive>          the base was captured with this option ENABLED. Turning it on is
#                            depicted; turning it OFF is not, because no screenshot of that exists.
#   layer <archive> <file>   art for this option, painted over the base when it is enabled. TWO hard
#                            requirements, both refused rather than worked around:
#                              - EXACTLY the base's pixel size. GamePreview will not scale it,
#                                because a control bar half a bar-height out of place is still a
#                                picture of a control bar and is still a lie about where it will be.
#                              - A 32-BIT PNG WITH AN ALPHA CHANNEL. A layer is a delta, and the
#                                alpha channel is how the art itself says so. This line used to
#                                permit an opaque full-frame image "which simply replaces everything
#                                under it"; that was wrong, and a cross-model review found why - an
#                                ordinary screenshot is opaque, so two enabled options with one each
#                                would leave only the higher-precedence one visible and the picture
#                                would show the other option in whatever state ITS capture had.
#   silent <archive> <why>   this option cannot change a picture like this one, and here is why.
#                            The reason is mandatory: it is the only thing that makes the claim
#                            checkable by whoever reads this next.
#
# An archive named by NONE of the three is reported to the player as "no preview available", and the
# caption under the picture names it. That is the intended state for an option nobody has captured
# yet - it is not a bug and it must not be papered over with art that was drawn rather than taken.
#
# PAINT ORDER IS NOT DECLARED HERE and must not be: it is the engine's, derived from the filenames
# at draw time. See PreviewArt.cs MountOrder.

gxlayers 1

# PROVENANCE. This is the project's own published screenshot, byte for byte - the file named by
# https://dl.wh1ter0se.dev/gxpreviews.txt on 17/08/2026 as ControlBar Pro's preview, downloaded from
# https://dl.wh1ter0se.dev/gxpreview/cbpro-1600x840.jpg and verified against the sha256 that
# document declares for it:
#
#   sha256 c156ec45fb422f3a39aa4a804a97099c77b440fbc3fa88ecb3221a9679bf2ce2
#   348076 bytes, 1600x840, captured from artifact gxopt_82c9bc3d.zip
#
# It is embedded rather than fetched because fetched art is not there when the launcher is offline,
# and "Preview unavailable offline" was the only sentence the previous preview boxes ever showed.
# 348 KB against the launcher's ~63.5 MB runtime tier is about half a percent.
base cbpro-1600x840.jpg
caption In game on Twilight Flame, captured with ControlBar Pro on (payload gxopt_82c9bc3d.zip).
artifact gxopt_82c9bc3d.zip

# The publisher's own document declares this shot as this option's screenshot, with the bullet
# "Captured in game on Twilight Flame, not a mock-up." So the base shows ControlBar Pro ENABLED -
# which is also why there is no honest way to show it switched off yet: that needs a second capture
# of the same scene with the archive renamed, and until somebody takes it the row says so.
shows 340_ControlBarProZH.big

# ONE MEMBER, AND IT IS A MENU. build-overlay-generated.py:67-71 builds !GXUI.big from exactly one
# file - Window\Menus\PopupHostGame.wnd - and overlay-optional.txt records the same thing along with
# the measurement that it moves assetID and not dataID. A .wnd layout for the Host Game popup cannot
# appear in a shot of a match in progress, so this option is not missing from the picture: it has
# nothing to be in it.
silent !GXUI.big it changes the Host Game screen, not the in-game view.

# The unit pips it carries are drawn only on renders 1440 px tall and taller (GXImageVariant.h); this base is 1600x840,
# where the retail 5x12 pip is drawn either way - so there is nothing to show at this size.
silent !GXUIHD.big it changes the unit pips at 1440p and 4K only; this picture is smaller.

# NOT CLAIMED, ON PURPOSE - three options with no art and no evidence, so the launcher tells the
# player exactly that rather than leaving the picture unchanged as though the option did nothing:
#
#   340_ControlBarPro-Fix1440ZH.big   1440-specific, and the base is 1600x840 - whether it changes
#                                     anything at this size is unmeasured, and a guess either way
#                                     would be a claim about somebody's screen.
#   340_ControlBarPro1440ZH.big       same.
#   !HotkeysLeikezeZH.big             it carries Data\English\generals.csf, which changes the hotkey
#                                     LETTERS drawn on the command buttons, so it genuinely is
#                                     visible in a shot like this one - there is simply no capture
#                                     of it. This is the entry most worth taking next.
#
# WHAT A CAPTURE NEEDS, so the next person does not have to work it out: the same scene twice at the

# base, and a real alpha channel, or GamePreview refuses it and the option goes back to reading "no
# preview available". Then add a 'layer' line here, and bump 'artifact' if the tier was rebuilt.
